# Windows、macOS、Obsidian 与 GitHub 同步

## 目录约定

`content` 目录本身就是 Obsidian Vault，也是博客唯一的内容源。Markdown 不需要复制到第二个文件夹：

```text
ctf-blog/
├─ content/
│  ├─ .obsidian/          # 可跨设备同步的 Vault 设置
│  ├─ posts/
│  │  └─ article-slug/
│  │     ├─ index.md
│  │     └─ screenshot.png
│  ├─ tags/
│  └─ templates/
└─ src/                   # 博客主题代码
```

文章目录使用英文小写 slug，例如 `sql-injection-bypass`；标题和正文可以使用中文。附件与文章放在同一目录，移动文章时不容易断链。

## 首次配置 Windows

1. 用 Obsidian 打开 `D:\\Note\\ctf-blog\\content`。
2. 在核心插件中启用“模板”，模板目录已配置为 `templates`。
3. 写作前执行 `git pull --rebase`，写完后先本地预览。

## 首次配置 macOS

```bash
brew install git node pnpm
git clone https://github.com/zhaochoudecat/ctf-blog.git ~/Documents/ctf-blog
cd ~/Documents/ctf-blog
pnpm install
```

然后在 Obsidian 中打开 `~/Documents/ctf-blog/content`。同一套 `.obsidian` 设置会由 GitHub 同步。

## 日常写作与发布

开始写作前：

```bash
git pull --rebase
```

新建 `content/posts/<slug>/index.md`，从 `content/templates/CTF WP.md` 插入模板。预览：

```bash
pnpm dev
```

确认无误后发布：

```bash
git add content
git commit -m "add <article-slug> writeup"
git pull --rebase
git push
```

`main` 是生产源码分支。当前生产站点为 [ctf-blog-mocha.vercel.app](https://ctf-blog-mocha.vercel.app/)；首次部署已完成。请在 [Vercel Git 设置](https://vercel.com/luoyunzong1/ctf-blog/settings/git) 中完成一次 GitHub 仓库连接，之后推送 `main` 会自动发布。多人或多设备同时修改同一篇文章时，不要强制推送；先处理 `git pull --rebase` 报告的冲突。

## 发布前检查

- 将 `draft` 改为 `false`。
- 不提交真实 Token、Cookie、SSH 密钥或仍然有效的 Flag。
- 图片使用标准 Markdown：`![说明](./screenshot.png)`。
- 代码块注明语言；可使用 `title="solve.py"` 和 `{3-6}` 行高亮。
- 执行 `pnpm check && pnpm build`。

## 可选：Obsidian Git 插件

如果希望在 Obsidian 内自动同步，可在 Windows 与 Mac 都安装社区插件 **Obsidian Git**，设置启动时拉取、提交前先拉取，并使用相同的 GitHub 凭证。仍建议在发布前通过终端检查 `git status`，避免把未完成内容设为公开。
